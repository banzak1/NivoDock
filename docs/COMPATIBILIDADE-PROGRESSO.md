## Leitores e limites

- **Pokémon:** mantém os leitores GBA/DS, Legends Z-A e Brilliant Diamond nativo existentes. Treinador/equipe são mostrados quando decodificados; outras edições não são confundidas com esses formatos. Seleção manual é preservada.
- **Dragonwilds JSON v83:** personagem, tempo salvo, XP de habilidades identificadas, receitas/construções, equipamento com ID identificado e missão/objetivo reconhecido. Níveis por XP, porcentagem de campanha e HP máximo não são inventados. IDs desconhecidos ficam fora da lista identificada.
- **Skyrim SE TESV v12:** personagem, nível, raça, local e XP do cabeçalho. Campanhas são separadas pelo identificador do arquivo quando presente, além da identidade. Habilidades, perks e equipamento dependem de um leitor de estruturas internas/plugins ainda não implementado.
- **Hytale Player v5 / Inventory v4:** personagem, mundo, item em uso, barra rápida, armadura, durabilidade real e vida salva. Os nomes de itens vêm do idioma da instalação local; nenhum Assets.zip é distribuído. Não inventa nível de personagem ou máximos de vida.
- **No Man’s Sky:** blocos LZ4/JSON, contexto ativo, unidades/nanites/mercúrio e tempo total do save. Expedição e campanha principal são distinguidas; saldos não são misturados. Naves/missões ainda não são interpretadas.
- **Megabonk:** formato JSON/AES-CBC publicado para 1.0.17, validado nos saves locais: moedas, desbloqueios, XP/partidas por personagem e estatísticas complementares do mesmo perfil. A chave desse formato é uma constante pública do jogo, não uma credencial de conta. Nenhum nível é inferido do XP.
- **Vampire Survivors:** SaveData JSON local com moedas e desbloqueios permanentes. Não confunde desbloqueios com nível de uma partida temporária.
- **Minecraft:** leitores separados Java (NBT BE/gzip) e Bedrock (NBT LE) para level.dat; mundo/modo/dia e nível Java quando o jogador está nesse arquivo. O mundo Java existente não foi associado ao Minecraft for Windows/Bedrock da biblioteca. Nenhum save Bedrock foi encontrado nesta auditoria; esse leitor foi validado com fixtures sintéticas.
- **Palworld, Isaac e Underground 2:** arquivos candidatos/contêineres encontrados; o progresso interno ainda não é decodificado. Palworld local usa PlM/Oodle. Não tratar falta de decoder como ausência do save.
- **Demais títulos:** sem leitor específico validado nesta entrega. Dados de conta online exigiriam integração e autorização próprias; nenhuma conta, token, senha ou sessão de autenticação foi consultada para criar esses cards.

## Seleção e atualização

Em **Gerenciar → Compatibilidade dos cards**, a aplicação mostra o estado real desta biblioteca. No card, escolha personagem/perfil para acompanhar o save mais recente desse perfil; a seleção de arquivo individual fixa aquele arquivo. **Usar mais recente** volta ao modo automático. Automático significa arquivo modificado mais recentemente, não personagem com nível mais alto. A escolha explícita ausente não é trocada por outro perfil.

Os dados representam o save gravado em disco, não telemetria da partida. Mudanças de arquivo/perfil e estatísticas complementares participam da atualização automática. Um arquivo incompleto durante a gravação conserva apenas a última leitura válida daquele mesmo arquivo, com aviso. Formato novo incompatível não é apresentado como uma leitura atual válida.

**Copiar arquivo** cria uma cópia apenas do arquivo indicado. Jogos com saves compostos podem exigir outros arquivos para um backup completo; o leitor não copia/sincroniza personagens automaticamente. Os leitores nunca escrevem nos saves. Seleções são guardadas no catálogo local.
